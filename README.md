# adbot v2: рассылка рекламы через зеркала

Один **основной бот** делает все рассылки в ваши группы. Рекламодатели создают
собственные **боты-зеркала**: там они присылают пост, выбирают группу и смотрят
статистику. Интервал, группы и слоты задают только владельцы в админке основного
бота. Ключей больше нет.

## Как это работает

- **Владельцы** (`/adm`): группы, зеркала, слоты, интервал, баны, рассылки,
  модерация, бэкап. Есть роль модератора (баны, пауза зеркал, одобрение постов).
- **Пользователь** выбирает один из двух способов: «Создать зеркало» (Telegram
  показывает окно с готовыми случайными именем и юзернеймом, подтверждение, Managed
  Bots) или «Подключить своего бота» (токен из BotFather).
- **Заявка.** Зеркало не запускается сразу: владельцам и модераторам приходит карточка
  с кликабельным именем, ID, username, датами и кнопками «Принять» / «Отклонить».
  Отклонили или никто не ответил за 24 часа (`APPLICATION_TTL_HOURS`) - заявка
  удаляется вместе с токеном, человеку приходит уведомление. Заявки также видны в
  `/adm` → Заявки.
- **Одно зеркало на пользователя.** В зеркале до 3 админов вместе с создателем.
- **Пост** принимается в зеркале (текст, фото, видео, GIF, файл, кнопки-ссылки),
  выбирается одна группа. Если группа одна, выбор пропускается.
- **Слоты:** 3 поста на токен по умолчанию, владельцы поднимают до 10 в карточке
  зеркала. Отчёт по посту идёт с момента его создания (или одобрения).
- Посты хранятся в приватном канале-хранилище и копируются оттуда
  (`copy_message`), поэтому смена основного бота их не ломает.

## Запуск (Docker)

1. В @BotFather создайте основного бота. Для автосоздания зеркал включите у него
   режим управления ботами (Bot Management Mode, настройка в BotFather/Mini App
   @BotFather, пункт про Managed Bots).
2. Создайте два приватных канала: **хранилище** и **бэкапы**. Добавьте основного
   бота админом в оба (в хранилище ему нужно право публиковать сообщения).
3. Скопируйте `.env.example` в `.env` и заполните (токен, ваш ID, ID каналов,
   ключ шифрования).
4. Запуск:

```bash
docker compose up -d --build
docker compose logs -f
```

5. В боте: `/adm` → Группы. Добавьте основного бота админом в рабочий чат, он сам
   предложит группу, останется нажать «Включить». Затем задайте интервал в
   Настройках.

Обновление: `git pull && docker compose up -d --build`. База лежит в `./data`
и при пересборке не теряется.

## Бэкап и миграция

- Бэкап уходит в `BACKUP_CHAT_ID` по расписанию и по кнопке «Бэкап». Файл
  `adbot-ГГГГММДД-ЧЧММ.db.gz`. Токены зеркал внутри зашифрованы.
- Восстановление или перенос на новый сервер:

```bash
docker compose down
gunzip -c adbot-XXXX.db.gz > data/adbot.db
# в .env должен быть ТОТ ЖЕ ENCRYPTION_KEY
docker compose up -d
```

## Если основного бота забанили

1. Создайте нового бота, добавьте админом в группы и в оба канала, откройте его и
   нажмите /start (владельцы из `OWNER_IDS` и добавленные в админке остаются).
2. В `.env` замените `BOT_TOKEN`, затем `docker compose up -d`. База, зеркала, посты
   и заявки сохраняются, зеркала запускаются сами.
3. `/adm` → Рассылка → «Сообщить о смене основного бота», укажите юзернейм нового
   бота. Уведомление уйдёт владельцам и админам всех зеркал через сами зеркала.
4. Пользователям старого основного бота написать нельзя: Telegram не позволяет
   боту писать первым. Держите публичный канал с актуальной ссылкой.

Все данные привязаны к Telegram ID, а не к боту, поэтому ничего не теряется.

## Структура

```
main.py             запуск: основной бот, зеркала, планировщик, бэкапы
config.py           настройки из .env
db.py               схема SQLite, индексы, вся работа с данными
handlers_main.py    пользователи: создание зеркала, токен, учёт групп
applications.py     заявки на зеркала: принять, отклонить, автоотклонение
handlers_admin.py   админка владельцев (/adm)
mirror_cabinet.py   кабинет в боте-зеркале
mirror_manager.py   запуск зеркал (отдельный polling на каждое)
posts.py            приём поста и сохранение в хранилище
scheduler.py        отправка по интервалам
backup.py           бэкап в канал
crypto.py           шифрование токенов (Fernet)
tg_raw.py           вызовы методов Managed Bots (getManagedBotToken)
tests/              проверки: test_db.py, test_scheduler.py, test_applications.py
```

## Что проверить на первом запуске

- **Managed Bots** появились в Bot API 9.6, методы вызываются напрямую
  (`tg_raw.py`). Название параметра у `getManagedBotToken` и формат ссылки
  создания (`MIRROR_LINK_TEMPLATE` в `.env`) сверьте с актуальной документацией
  Telegram. Если автосоздание не сработает, работает подключение по токену.
- Альбомы не поддерживаются, файлы больше 20 МБ тоже (ограничение Bot API на
  скачивание).
